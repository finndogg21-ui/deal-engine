## Phase 2 — RESEARCH (brief; workflow wvs2svhh7, 4 agents, all sourced)
The mobile contract for a content-dense B&W deal feed:
1. **16px minimum** body/input font — readability floor AND the iOS Safari no-zoom floor for
   inputs (ZIP/search). Never `user-scalable=no`. [verified]
2. **Type scale:** title 16-17px, price the prominent number, secondary/meta **≥14px floor**
   (retailer, was, facts), headings 28-40px. Nothing a user must read below 14px. [verified]
3. **Line-height ≥1.5** on wrapping text (WCAG 1.4.12). [verified]
4. **Single-column list** cards for a decision-by-numbers feed (not a shrunk grid); identical
   field order every card. [NN/g, Baymard — verified]
5. **Price hierarchy:** now-price prominent, was struck/secondary, discount grouped tight;
   % under $100, $ over $100. [Baymard — verified]
6. **Tap targets ≥44px** (aim 48), ≥8px gaps, hit area via padding. [Apple HIG / Material 3 / WCAG 2.2 — verified]
7. **No horizontal overflow at 320px** (WCAG 1.4.10 Reflow). [verified]
8. **Contrast ≥4.5:1** for accents + grey meta at real size; grey no lighter than #767676. [verified]
9. **Monochrome hierarchy = 4 channels:** SIZE (big steps), WEIGHT (400/500), CASE (uppercase
   meta), RULES+SPACING; tabular-nums + right-aligned prices. [Pimp My Type / NN/g — verified]

## Phase 3 — COMPARE (gap list; code + live 375px measurement)
Base system is solid (17px body, 1.5-1.6 line-height, AA accents, reduced-motion, --s scale,
44px on some controls). The gap is one thing, and it is large:

- **MISSING — deal card type shrunk to six-across sizes on full-width mobile cards.** The
  "SIX-UP CARD DENSITY" block (`dashboard.css`) sizes card type for ~200px cards (6 across) but
  is **never undone at the single-column (≤430px) breakpoint**, where the card is full-width.
  Measured LIVE at 375px (card width **327px**): title **12.5px**, retailer **9px**, was
  **11px**, facts **10px** — all far below the 14/16px floors, on a card with ~200px of unused
  width. This is the #1 mobile-readability failure the research names. Evidence: computed
  styles via the in-app browser at 375px; screenshot in the cycle.
- PARTIAL — `.clr-reveal` tap target ~9.5px text with small padding (<44px). (item 2 territory)
- MEETS — no horizontal overflow at 375px (docWidth==vw). Reflow is fine.
- Deferred (bigger layout, next cycle): image plate is tall (16/11) and top-full-width; research
  favors a right-hand thumbnail for a decision-by-numbers feed. Not this cycle (not low-risk-small).
